# 公司报告模板设计（GitHub Pages 静态站）

日期：2026-05-15

## 背景与目标

用户正在搭建一个基于 GitHub Pages 的静态站，承载个人投研报告。已有 `template-by-user.md` 作为初稿，本设计在其基础上补全章节、定义元数据与页面结构，使每家公司有一份可持续更新、可在小圈子内分享的"活页"。

## 关键决策

1. **受众**：小圈子分享（朋友 / 社群 / 订阅者）。读者有金融基础，但不一定熟悉具体公司，解释性内容保留，基础术语科普省略。
2. **页面模型**：**一家公司一个活页**（单一 URL，内容持续更新覆盖）。重大重写时可手动归档旧版到 `archive/`，日常增量更新只改主页。
3. **更新日志**：主页**不**维护内嵌 changelog；改为一个独立子页面 `changelog.md`，通过链接跳转。日常 git history 即完整变更记录。
4. **顶部速览**：30 秒扫读时呈现 **核心结论文字段 + 关键数据表**（D 组合）。
5. **骨架风格**：**中道版** —— 默认精瘦，业务模式 / 估值分析两节允许深度展开多个子节，其余节保持简短。
6. **Must-have 新增章节**：风险 / 反向论证、财务表现概览、催化剂。
7. **可选章节**：管理层与资本配置（有内容就填，没内容删整节）。

## 完整模板结构

### Frontmatter（YAML）

```yaml
---
title: SOFI - SoFi Technologies
ticker: SOFI
market: US           # US / JP / HK / CN ...
sector: Financial Services
last_updated: 2026-05-14
latest_filing: 2026-Q1
view: Long           # Long / Watch / Pass  (可选)
tags: [fintech, digital-bank]
---
```

- `view`：可选个人观点标签，便于网站首页做 Long/Watch/Pass 筛选
- `tags`：支持跨公司主题汇总

### 页面头部

```markdown
# {TICKER} — {Company Name}

> 最后更新：YYYY-MM-DD | 最新财报：YYYY-QN | [更新日志 →](changelog.md)
```

### 1. 核心结论

3-5 句话讲清：
- 当前观点（值不值得买 / 持有 / 观望 / 规避）
- 基准合理价值区间 + 当前股价的位置
- 最关键的看多 / 看空点
- 是否有安全边际

### 2. 关键数据

固定核心行 + 公司可加自定义行：

| 指标 | 当前值 |
|---|---:|
| 股价 | $X (YYYY-MM-DD) |
| 市值 / EV | $XB / $XB |
| Forward P/E | Xx |
| P/B / P/TBV | Xx / Xx |
| Revenue Growth (TTM / YoY) | X% |
| Operating / Net Margin | X% / X% |
| 净负债 / EBITDA | Xx |
| 52 周区间 | $X - $X |
| 分析师中位目标价 | $X |

特殊指标（按公司行业灵活追加）放在表格末尾，明确标注。

### 3. 公司概要

- **基本信息**：行业 / 总市值 / 雇员数 / 上市地 / 自有资本比率 / 主要市场
- **业务描述**：1-2 段，讲清楚公司在做什么、怎么赚钱、护城河来源

### 4. 图表区

- 10 年股价：[Yahoo Finance →]()（周线 / 折线，GitHub Actions 每日更新）
- 近 10 年 PER / PBR 折线图（脚本生成嵌入）+ 数据表：

| 年度 | 期末股価 | EPS | BPS | PER(x) | PBR(x) |
|---|---:|---:|---:|---:|---:|

### 5. 业务模式

精瘦默认；可按公司复杂度拆子节。

#### Business Segments（可选）

公司有清晰多板块时使用：

| 板块 | 营收占比 | 利润占比 | 增长率 |
|---|---:|---:|---:|

每个板块下跟一段定性描述。

### 6. 财务表现

近 3-5 年关键指标趋势表：

| 年度 | Revenue | YoY | Operating Margin | Net Income | EPS | FCF |
|---|---:|---:|---:|---:|---:|---:|

跟一段文字（3-5 句）：趋势关键变化、驱动因素、是否有结构性改善 / 恶化。

### 7. 竞争与护城河

护城河来源（3-5 点 bullet）。

**同业对比**（固定 4 列 + 行业可换 1-2 列）：

| 公司 | Ticker | 市值 | Forward P/E | P/S TTM | Revenue Growth | [行业指标 1] | [行业指标 2] |
|---|---|---:|---:|---:|---:|---:|---:|

固定 4 列：公司+Ticker、市值、Forward P/E、Revenue Growth。
半固定列：P/S TTM（银行 / 保险除外几乎都有意义）。

行业可换列推荐：

| 行业 | 推荐替换列 |
|---|---|
| 银行 / 消费金融 | P/TBV, ROE |
| SaaS / 软件 | Rule of 40, Net Revenue Retention |
| 半导体 / 制造 | EV/EBITDA, ROIC |
| 消费品 | Operating Margin, ROE |
| 能源 / 大宗 | EV/EBITDA, FCF Yield |
| 房地产 / REIT | P/NAV, Cap Rate |

### 8. 催化剂 / 关注点

**短期（< 6 月）：**
- 下一次财报日（YYYY-MM-DD），关注什么 KPI
- 即将到来的产品 / 合规 / 监管节点
- 可能影响估值的具体事件

**中期（6-18 月）：**
- 战略落地的检验点
- 关键 KPI 需要达到什么水平才能验证 bull case

### 9. 风险 / 反向论证

**关键风险（按可能性 × 影响排序，3-5 条）：**
- **{风险名}**：触发情况、对估值 / 业务的影响、监控信号

**什么情况下我会撤回结论？**

1-2 句明确 thesis 失效的硬条件（例："信贷损失率连续两季 > X%"）。

### 10. 管理层与资本配置（可选）

有内容就填，无内容删整节：
- 核心高管 / 内部人交易动向
- 分红 / 回购 / 资本开支政策
- 大股东结构变化

### 11. 估值分析

允许深度展开。

#### P/TBV
方法说明 + 当前 vs 历史 + 推导

#### 本期 EV / Adjusted EBITDA

#### N 年 EPS 折现
明确假设：增长率、折现率、退出倍数、敏感性表

#### 估值结论

| 情景 | 合理价值 | 触发条件 |
|---|---:|---|
| 保守 | $X | ... |
| 基准 | $X | ... |
| 乐观 | $X | ... |

**当前 vs 合理价值**：当前 $X 相对基准 $Y，溢价 / 折价 X%。

### 12. 后续关键问题

开放式问题列表，下一份报告需要回答 / 验证的事项。

### 13. 来源

- 财报 / 8-K / 10-Q / IR 链接
- 第三方分析、新闻报道（注明日期）
- 数据来源（Yahoo Finance / SEC / EDINET 等）

### Footer

```markdown
---

> 最后修改：YYYY-MM-DD · [完整更新日志 →](changelog.md)
```

## 文件组织约定

```
company-reports/
  {ticker}-{company-name}/
    index.md            ← 活页主页（套用本模板）
    changelog.md        ← 独立更新日志子页面
    archive/            ← 仅在重大 thesis 重写时使用
      YYYY-MM-DD-snapshot.md
```

与现有 AGENTS.md 中 `YYYY-MM-DD-reports.md` 的关系：
- 历史已有的日期文件保留为既有快照，不强制迁移
- 新建公司目录使用 `index.md` 作为活页入口
- AGENTS.md 中关于报告写作要求（中文为主、来源标注、事实/估算/判断区分）继续适用

## changelog.md 结构（简单约定）

```markdown
# {TICKER} 更新日志

- **2026-05-14**：Q1 财报更新，合理价值上调至 $16-19；新增 Galileo 整合风险讨论
- **2026-04-10**：首次建仓分析，基准价值 $14-17
```

倒序排列，每条 1-3 行，重写时往上加。
