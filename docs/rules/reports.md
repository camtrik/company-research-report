# 公司报告写作规则

适用于所有 `company-reports/` 下的 markdown 报告。

## 目录约定

公司报告统一放在：

```text
company-reports/{ticker}-{company-name}/YYYY-MM-DD-reports.md
```

- `{ticker}` 使用股票代码，优先大写，例如 `AAPL`、`NVDA`、`TSLA`、`6098`、`4568`。
- `{company-name}` 使用公司**本地语言名**，小写 kebab-case：
  - 日本市场（JP）→ 日语正式名称，例如 `6098-リクルートホールディングス`、`4568-第一三共`、`3632-gree`。
  - 美股等其他市场 → 英文常用名，例如 `NOW-servicenow`、`SOFI-sofi`、`AAPL-apple`。
  - 若本地语言名过长或包含特殊字符，可用广为认知的缩略名。
- 报告文件名必须使用实际报告日期，格式为 `YYYY-MM-DD-reports.md`。
- 同一公司不同日期的报告保留为独立文件，不要覆盖历史报告。
- 如果需要补充原始材料、截图、表格或模型文件，可放在同一公司目录下，并使用清晰文件名。

## 写作要求

报告正文应优先使用中文撰写。公司名、产品名、财务科目、行业术语和引用标题可保留英文；如果用户明确要求英文或原始报告已有固定英文模板，则按用户要求或既有模板执行。

新建或更新 `YYYY-MM-DD-reports.md` 时，结构参考 [`docs/template.md`](../template.md)。

可以根据任务需要增删章节，但报告应至少覆盖：公司做什么、收入和利润质量、增长驱动、竞争格局、主要风险、估值或市场预期、后续需要验证的问题。

## 研究与引用

- 涉及当前股价、财报、估值、管理层、新闻、监管文件、分析师预期等可能变化的信息时，必须获取最新资料后再回答或写入报告。
- **抓数据走 skill**：需要拉股价、财报、估值、分析师预期、社交情绪、相关性、ETF 溢价、期权链等数据时，优先使用项目已安装的 `finance-*` 系列 skill（`finance-market-analysis:*`、`finance-social-readers:*`、`finance-data-providers:*`）。具体哪个 skill 看它的 description；不要自己写 yfinance / 爬虫脚本绕过 skill。
- 优先使用一手或高可信来源：公司 IR、SEC 文件、交易所公告、财报电话会、官方新闻稿、主流财经数据源。
- 报告中的关键事实、数字和判断应尽量附来源链接或来源说明。
- 区分事实、估算和个人判断。对假设性内容使用明确措辞，例如"假设""可能""需要进一步验证"。
- 不要把未经验证的市场传言写成事实。

## 分析风格

- 默认使用中文输出，除非用户指定英文或报告已有固定英文格式。
- 写作应直接、审慎、可操作，避免空泛形容词。
- 投资结论需要说明核心依据和反向风险。
- 对公司进行比较时，明确同行选择理由和比较指标。
- 对估值进行讨论时，明确使用的方法、关键假设和敏感变量。

## 文件编辑规范

- 新增报告前先检查对应公司目录是否已存在。
- 更新旧报告时保留原有有效内容，不要无故删除历史分析。
- 不要改动与当前任务无关的报告或研究文件。
- 如果同一事实在多个报告中需要更新，先说明影响范围，再进行修改。
